# 차량 공조 자동 전환 판단

## 기존 코드 분석과 변경 범위

프로젝트는 Java 17, Android Activity 한 개와 순수 Java `VentilationPolicy`로 구성됩니다. 실제 공사 API, 위치 제공자, Pleos 제어 인터페이스는 없습니다. 기존 입력 경계는 `Observation(Road, Work, Air, elapsedSeconds, automaticEnabled, driverIntervened, defrost)`이며 `MainActivity.Scenario`와 주행 단계가 데이터를 생성합니다. 이 구조와 기존 시연을 유지하고 현재 공조 모드를 별도 인자로 추가했습니다. 독립 초안의 별도 패키지는 가져오지 않았습니다.

기존 정책은 요청 시점에 시작을 기록했고, 공사 종료/통과 시 대기가 보통이어야 복원했습니다. 변경 후에는 실제 적용 성공 확인 후에만 소유권을 기록하고, 구간 통과 후 대기 등급에 관계없이 이전 모드를 복원합니다. 기존 45초 시연용 상한은 유지하되 제어권 반환이라는 미확인 차량 API 대신 원래 모드의 RESTORE를 반환합니다. 운전자/김 서림 우선 시에는 RESTORE를 보내지 않습니다.

## 판단과 적용 계약

- `SWITCH`: APPROACH + ACTIVE + POOR + 자동 전환 켜짐 + 원래 모드가 FRESH_AIR/AUTOMATIC일 때 내기순환을 요청합니다.
- `RESTORE`: 앱 요청의 적용 성공이 확인된 경우에만 이전 모드를 대상으로 요청합니다. 구간 통과, 자동 전환 끄기, 시연용 45초 상한이 조건입니다.
- `KEEP`: 다른 경우이며 `reason`에 정보 실패, 반대 방향, 이미 내기순환, 우선권, 대기 중 등 이유를 담습니다. target은 null, requestId는 0입니다.

`SWITCH/RESTORE`는 고유 requestId와 target을 포함합니다. 제어 담당은 실제 적용 직전 `isPending(requestId)`와 최신 운전자/김 서림 상태를 확인하고, 실제 결과를 `onApplied(requestId, applied)`로 전달해야 합니다. 요청 자체는 소유권을 만들지 않습니다. 응답 대기 중에는 중복 명령을 내지 않고, 명시적 실패 응답 뒤 다음 평가에서 조건이 유지되면 재시도합니다. 잘못된/중복/취소된 응답은 무시합니다.

운전자 직접 조작 또는 김 서림 제거가 감지되면 대기 중 명령과 앱 소유권을 버리고 해당 주행 동안 자동 전환을 중단합니다. 이는 공조를 원래 모드로 강제로 변경하는 동작이 아닙니다. `MainActivity`의 버튼은 운전자/김 서림 동작 자체를 별도로 가상 반영합니다. 같은 모드를 다시 선택하는 직접 조작도 이벤트로 전달해야 합니다. 현재 모드가 앱의 내기순환에서 다른 알려진 모드로 바뀐 경우에도 외부 조작으로 판단해 소유권을 포기합니다.

정책은 **주행 및 대상 공사 구간별 인스턴스**입니다. `Road.PASSED`는 앱이 추적하던 같은 구간의 통과라는 계약입니다. 다른 구간의 PASSED를 섞으면 안 됩니다. 여러 구간/중첩 구간을 동시에 관리하는 집계는 아직 구현하지 않았습니다.

## 위치/공사 데이터 경계

`WorkZoneApproach`는 외부 SDK와 무관한 선택적 분류 어댑터입니다. 아직 확인되지 않은 API를 실제 인터페이스로 가정하지 않습니다. `Source`에 테스트용 Snapshot 제공자를 넣거나, 향후 확정된 위치/공사 제공자를 연결할 수 있습니다. 기존 화면은 기존 Road 단계 시연을 계속 사용합니다.

- Position: 도로 ID, 도로 진행 방향으로 증가하는 누적 거리(m), 차량 방위각(도)
- Zone: 같은 기준 도로 ID, 시작/종료 거리(m), 대상 도로 방위각, 진행 상태
- 같은 도로·방향에서 시작점 전 접근 거리 이내면 APPROACH, 구간 내부/통과 여유 거리 이내면 WORK_ZONE, 그 이후면 PASSED입니다.
- 반대 방향은 OPPOSITE, 다른 도로·불확실한 방향·잘못된 수치·조회 예외/실패는 UNKNOWN입니다. ACTIVE/ENDED/UNKNOWN은 제공받은 공사 진행 상태를 그대로 전달합니다.
- 접근 거리, 통과 여유 거리, 방위각 오차는 생성자 주입값이며 테스트의 100m/10m/45도는 제품 확정값이 아닙니다.

이는 위경도를 도로에 투영하는 맵 매칭 구현이 아닙니다. 실제 위경도, 유효 시간, 진행 방향, 경로 일치 여부를 위 값으로 변환하는 계약은 팀과 API 문서를 확인해야 합니다. 데이터가 오래되거나 진행 여부가 불명확하면 UNKNOWN으로 정규화해야 합니다. UNKNOWN에서는 새로운 전환을 시작하지 않습니다. 기존 앱 변경은 유지하고, 별도로 신뢰 가능한 동일 구간 PASSED가 확인되면 조회 실패 중에도 복원합니다.

## 실행과 검증

`sh scripts/test-ventilation.sh`는 임시 디렉터리에 정책·분류기·테스트만 컴파일하고 실행 후 삭제합니다. 서드파티 라이브러리는 필요 없습니다. 현재 Java 21 환경에서 Java 17 소스/바이트코드 옵션으로 **210 assertions 통과**했습니다. 축소된 JDK에 --release용 시스템 심볼이 없어서 -source/-target을 사용합니다. 전체 앱 Java 소스도 Maven Central의 Android 4.1.1.4 스텁 JAR에 대해 컴파일해 시연 호출부와 정책의 타입 일치를 확인했습니다. 이는 Android SDK 36/Gradle 빌드 또는 기기 실행 검증을 대신하지 않습니다. 실제 JDK 17 및 Android APK 빌드는 별도 검증이 필요합니다.

같은 차량 위치/먼지 등급에서 공사 진행 여부만 변경, 반대 방향, 조회 실패, 먼지 보통/불명, 이미 내기순환, 통과 후 먼지가 나쁜 경우, 자동 모드/외기 모드 복원, 앱이 바꾸지 않은 모드 유지, 자동 제어 끄기, 시간 상한, 운전자/김 서림 우선, 명령 취소, 적용 실패 재시도, 반복 호출/중복 응답, 외부 모드 변경, 도로/방위각 경계, 잘못된 좌표, 제공자 예외 및 인터럽트를 검증합니다.

## 남은 실제 연동 사항

1. 실제 공사/PM2.5 제공자의 데이터 계약·최신성·조회 실패 규칙, GPS/주행 방향의 맵 매칭 및 대상 구간 ID 확정
2. Pleos 현재 모드 조회와 실제 적용 결과 콜백, 실제 자동 환기 설정 전체를 스냅샷/복원하는 방법 확인. 현재 Mode는 시제품 수준의 정규화 값이며 전체 HVAC 설정을 의미하지 않음
3. 운전자 조작/김 서림 이벤트와 자동 제어 명령의 원자적인 우선순위·취소 보장
4. 명령 타임아웃/연결 끊김 시 실제 적용 여부 재확인, 앱 재시작 시 소유권 처리, 회차/우회/다중 공사 구간 처리
5. 단조 증가하는 elapsedSeconds 공급. 시작 시간은 요청 시점이므로 늦은 성공 응답은 보호 시간을 연장하지 않음

정책 호출, 실제 적용 및 결과 콜백은 제어 계층에서 직렬화해야 합니다. `isPending` 확인과 실제 차량 명령 사이의 경쟁을 이 클래스만으로 제거할 수는 없습니다. 취소된 명령이 차량에서 늦게 실행되는 문제는 제어 담당과 차량 측에서 막아야 합니다. 응답이 없다는 이유만으로 실패 처리해 자동 재전송하지 마세요. 실제 적용 여부를 확인한 뒤 결과를 전달해야 합니다. 실차 제어는 이 변경에 포함하지 않았습니다.
